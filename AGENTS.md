## 4. Intake protocol

The owner drops files with whatever names his phone, scanner or download gave them. He will not rename anything. That is your job, every time.

### 4.1 Fixed mapping for the current assets

| Source | Destination | Processing |
|---|---|---|
| `website front video.mp4` | `public/media/hero.mp4` | Re-encode H.264 (CRF ~23, faststart) **and** a VP9/WebM. Target under 4 MB. Extract `hero-poster.jpg` from a representative frame. |
| `3D scroll laptop screen wallpaper.png` | `public/media/screen/` | Downscale to `screen-om-01-2048.jpg` and `screen-om-01-1024.jpg` (16:10, no crop), then KTX2/Basis for production. **Never serve the 8K PNG.** |
| `Osama Minhas - CV.pdf` | `public/documents/cv/osama-minhas-cv.pdf` | Downloadable artifact only. **Do not extract facts from it** — the two-column layout extracts badly. All written content comes from `docs/CV-SOURCE.md` (§4.4). |
| `AI certifications/*` | `public/documents/certificates/ai/` | Per §4.2. |
| `CA certificate and degree/*` | `public/documents/certificates/ca/` and `public/documents/degrees/` | Per §4.2. Split certificates from academic degrees. |

Then move the originals into `_source/` so the repo root is clean. **Move, do not delete.**

### 4.2 Per-document procedure

1. **Open and read every file.** Extract: title, issuing body, holder name, issue date, credential/ID number, and what it certifies. Do not infer from the filename.
2. **Report before writing.** Output a table: source file → detected title/issuer/date → target category and sub-category. Ask the owner to correct anything you inferred rather than read.
3. **After approval:** rename to kebab-case (`anthropic-claude-code-101.pdf`, `icap-ca-inter.pdf`, `gcuf-associate-degree-commerce.pdf`), copy into place, add the entry to `content/certifications.ts` or `education.ts`, then run `npm run thumbnails && npm run check:docs`, and log it in `docs/DECISIONS.md`.
4. Illegible, cropped or name-mismatched scans get flagged, not silently published.
5. **Filenames with spaces must never reach `public/`.** They break URLs, imports and some static hosts.

### 4.3 Privacy

Personal identifiers that appear on scans but not on the public CV — CNIC, roll numbers, home address, date of birth — are not published. Crop or blur them in the generated thumbnail. The credential number itself may stay when it is the thing being verified.

### 4.4 Written content

`docs/CV-SOURCE.md` is the authoritative record of every fact on this site: identity, profile, projects, competencies, stack, experience, education, certifications, languages, interests, and the permanent `id` values. Populate all of `content/` from it.

- **Facts are locked.** Dates, employers, institutions, credential IDs, standards and technology names are copied exactly. Never adjust a date, expand an abbreviation, merge two roles or tidy a title.
- **Prose is not locked.** Rewrite the CV-register paragraphs into web copy — shorter, active voice, no filler, subject to the banned-words list in §7. Do not change what they claim.
- **`id` values are permanent.** Other content files reference them.
- The file ends with a list of facts that are deliberately absent. **The CV contains no metrics, percentages or quantified results — do not manufacture any.** Anything the site needs but the file lacks goes to §12 as an open question.

## 7. Design rules

- All colour and type values are CSS custom properties in `src/styles/tokens.css`. Tailwind reads from them. A raw hex or `font-family` anywhere else is a bug.
- **Palette is derived from the cinematic reference:** deep black backgrounds (`#000000`), warm off-white text (`#E8DFD8`), and a gold/warm accent (`#cbb59d`) for selection and highlights.
- Three type roles: display, body, utility/mono. Self-hosted via `next/font/local`. No Google Fonts CDN calls. The mono face carries real weight here — this person's world is terminals, ledgers, audit trails and config files. Use it for dates, credential IDs, section markers and document metadata.
- **Banned looks** — these read as machine-generated and the owner has rejected them: cream `#F4F1EA` + high-contrast serif + terracotta `#D97757`; near-black with a single acid-green accent; broadsheet hairline-rule newspaper grid. If a proposal lands on one, redo it and say what changed.
- Dark is default. Light mode optional; if built, WebGL materials must not break in it.
- Spend boldness in the cinematic typography, the hero video, and smooth scroll animations. Everything else stays quiet and disciplined. Cut any decoration that does not serve one of the three.
- Copy is design material. Plain verbs, sentence case, active voice, no filler. **Never write** "passionate", "innovative", "cutting-edge", "leveraging", "seamlessly", "journey", "elevate".

## 10. Engineering standards

**Stack:** Next.js (App Router) + TypeScript strict · Tailwind · framer-motion · lenis · GSAP ScrollTrigger + Lenis · framer-motion for DOM motion · react-pdf. Must build with `output: 'export'`.

**Cinematic discipline:** Optimize framer-motion variants, ensure Lenis scroll is buttery smooth, and lazy-load videos/images.

**Content schema:** everything derives from `content/types.ts`. Dates are `"YYYY"` or `"YYYY-MM"` strings, never free text; ongoing roles use `endDate: null`. Every entity has a stable kebab-case `id` — ids are permanent, never renamed, because other files reference them. Relationships are by id, never string matching: projects and certifications carry `stackIds`, and the stack section builds its hover-highlight graph from those.

**Quality floor — verified, not assumed:**
- Lighthouse ≥ 90 desktop / ≥ 80 mobile performance, ≥ 95 accessibility. LCP < 2.5s, CLS < 0.05.
- Full keyboard traversal, visible focus rings, skip link. Canvas is `aria-hidden` and never a focus trap.
- Real heading hierarchy, `<time>` for dates. The entire CV reads correctly in a screen reader.
- Responsive 360px → 2560px. The scroll narrative must still make sense on a phone.
- JSON-LD `Person` schema with `alumniOf`, `hasCredential`, `knowsAbout`, `worksFor`. Sitemap, robots, OG image.

**Code:** strict TypeScript, no `any`, no `@ts-ignore`. Named exports. No dead code, no commented-out blocks — delete rather than comment.

## 11. Working protocol

**Order of work.** (1) intake → (2) design plan → (3) content layer + every section in plain 2D → (4) certificate rail and viewer → (5) 3D canvas and scroll narrative → (6) performance and accessibility pass. **Pause for owner review after each.**

**Ship a fully working non-3D site at step 3.** The 3D is a layer on top of something that already works, never a dependency for reading the content.

Before a large change, state the plan in a few lines and wait. Large means: a new dependency, an architecture change, more than ~5 files, or anything touching `content/types.ts`. Small changes, just do.

**Explaining work.** The owner is technical — Docker, n8n, MCP, agent harnesses — but not a frontend specialist. Skip basics he has demonstrated. Explain WebGL, GSAP timelines and CSS layout properly; assume no prior React Three Fiber knowledge. Numbered steps when he executes something himself, one step at a time, no previewing ahead.

**Verify before claiming done.** Run the build. Run `check:docs`. Open the page. Screenshot it and actually look. **Never report a feature complete on the basis that the code looks correct** — especially the rail: sweep the cursor across it fast and confirm it flips cleanly.

**Commits:** conventional, one logical change each — `feat(rail): pointer-distance peek with spring falloff`. Never commit `_source/`, `node_modules`, or generated thumbnails.

**Commands you maintain:**
```
npm run dev          npm run build
npm run intake       # process new files
npm run thumbnails   # regenerate document posters
npm run check:docs   # content ↔ disk consistency, fails the build on mismatch
```
